What Load returns : faux. Load("murs/nexistepas.png") rend false, et l'image reste invalide : IsValid() vaut faux, Width() et Height() valent 0. C'est ce que dit la ligne du programme, imprimee par le programme lui-meme : "charge : 0, valide : 0, largeur : 0, hauteur : 0". Rien n'est lance, rien n'est affiche par cet appel : le seul signe de l'echec est cette valeur de retour.

Why nothing crashes : parce que l'echec est un resultat, pas une exception. NkImage est un type valeur : un chargement rate laisse l'image dans un etat valide mais vide, et c'est a l'appelant de tester ce que Load rend avant de s'en servir. Tant que le programme ne lit pas les pixels, il continue : l'image vide n'a ni largeur ni hauteur, et lire un pixel d'une image invalide rend (0, 0, 0, 0) au lieu de planter. Pour la texture, c'est le moteur qui prend la decision a ma place : la bibliotheque de textures ecrit une erreur dans le journal (la ligne de journal.txt, qui nomme le fichier) puis rend a la place la texture d'erreur du moteur, et le rendu continue normalement, a la meme cadence. C'est pour cela que c'est difficile a voir : le programme tourne, rien n'est signale a l'ecran, l'avertissement est dans logs/app.log, dans le dossier d'ou le programme a ete lance, et seul celui qui lit le journal l'apprend.

What the wall shows : le mur du fond n'est pas du gris, il est uni et violet-magenta (valeur mesuree sur mur-absent.png autour de (77, 1, 67), assombrie par l'eclairage ; la texture d'erreur du moteur est un magenta pur). Le moteur a choisi ce repli visible parce qu'un moteur qui s'arrete quand un decor manque serait inemployable, alors qu'une couleur qu'on n'a pas choisie se repere tout de suite sans arreter la scene. Le defaut n'est pas le repli, c'est qu'il soit silencieux pour qui ne regarde pas le journal : devant ce mur violet, je ne cherche pas dans le code de rendu, je lis le journal.
