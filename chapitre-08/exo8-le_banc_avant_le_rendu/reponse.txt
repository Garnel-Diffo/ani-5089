Ce que le banc refuse : (What the bench refuses:) trois choses, et chacune est une ligne de sortie.txt. Un : emprunter deux fois de suite (`refus 1`). Le premier AcquireImage reussit, le second retourne false, et il ne change rien : l'index de l'appelant reste a 77, la valeur qu'il avait avant l'appel, et le ReleaseImage qui suit rend normalement l'emprunt d'origine. Deux : rendre sans avoir emprunte (`refus 2`). ReleaseImage retourne false et l'anneau ne bouge pas (anneau sur 1 avant, sur 1 apres) : s'il avancait, une image serait sautee a chaque faute. Trois : creer une chaine plus grande que le maximum (`refus 3`). Create(5) avec un maximum de 4 retourne false et la chaine reste invalide ; le banc verifie aussi que 4, le maximum lui-meme, est accepte. Tout le mecanisme tient dans un booleen et deux comparaisons, et refuser n'est pas planter : une methode qui retourne false laisse le programme decider. Les six tours d'avant montrent que l'anneau boucle sur trois images : 0 1 2 0 1 2, et que la derniere image rendue (GetLastReleasedIndex) est a chaque tour celle qu'on vient de dessiner, alors que l'anneau pointe deja sur la suivante (le tour 3 rend 2 et l'anneau est sur 0).

Pourquoi un simulateur permissif serait pire : (Why a permissive simulator would be worse:) parce qu'il ne se contenterait pas d'etre inutile, il serait trompeur : il vous laisserait ecrire du code qui ne marche que chez lui, et le vrai runtime, qui sanctionne ces trois fautes, ne le laisserait pas passer le jour ou il remplace le simulateur, avec un casque sur la tete et sans debogueur. Je l'ai verifie sur le banc : j'ai fait trois copies permissives de chaine.h, en retirant chaque fois une seule condition (`|| mAcquise` dans AcquireImage, `|| !mAcquise` dans ReleaseImage, `nombreImages > kImagesMax` dans Create), et j'ai relance banc.cpp, inchange, sur chacune. Le banc a rendu 1 les trois fois, avec exactement une ligne ECHEC a chaque fois : sans le premier refus, `AcquireImage deux fois de suite -> ok puis ok`, et le second appelant recoit l'image 0, la meme que le premier, donc deux rendus dans la meme image (le compositeur la lirait a moitie dessinee) ; sans le deuxieme, `ReleaseImage sans emprunt -> ok (anneau sur 1 avant, 2 apres)`, une image sautee sans que rien ne le dise ; sans le troisieme, `Create(5) -> ok` sur un tableau de quatre poignees, et la cinquieme s'ecrirait hors du tableau (ce dernier point est un raisonnement sur le code, je n'ai pas execute d'ecriture hors tableau). Ces fautes ne se voient pas avec une seule image : le modulo ramene toujours a zero, c'est ce qui les cache. Le simulateur strict les attrape sur mon bureau, avec un debogueur, alors qu'une version permissive les laisserait vivre jusqu'au jour ou le runtime en donne trois images. C'est le prix d'une garantie : un booleen et une comparaison, pour une erreur qu'on ne diagnostiquerait jamais a trois heures du matin, devant une image sur deux qui est noire.
